# ADR-001: проверить полномочия Restricted до выбора хранения

Статус: **Proposed**. Дата: 2026-09-27. Commit: `42a84aec8abf72e54958ddf8ca9480514cc0d390`.

## Контекст

R03/R09 и I01/I06 требуют закрыть hidden history в согласованной модели угроз. Account/Network предоставляют обычные полномочия Telegram-сессии (E03/E04/E16 в ../02_REPOSITORY_MAP.md). Две DB не создают серверное ограничение выбранных чатов. В первом проходе T3/T4 не были исключены; 2026-09-28 владелец явно выбрал T1 и исключил T2/T3/T4 (D01).

## Предлагаемое решение

AUTH-01 выполнен, D01 принят по модели угроз. До production bootstrap/storage применить T1 к проекту и проверить штатные пути. Не заявлять защиту от произвольного использования полной auth (T3/T4): AUTH-01 опроверг такую гарантию для проверенных RPC. После D01 оценивать кандидата по штатным путям T1; успех RPC из debugger не является основанием отклонить кандидата в этой модели.

## Альтернативы

- Начать UI-фильтры: не закрывает файловую/сетевую границу, не подходит как protected implementation.
- Сразу две DB: проверяет организацию хранения, но откладывает блокер авторизации.
- Offline projection без auth: возможное изменение продукта, требует владельца.
- Внешний доверенный посредник: отдельные scope и threat model; не разрешён этим ADR.

## Последствия и принятие

Результаты AUTH-01 и решение владельца D01 получены. Защита от T2/T3/T4 исключена владельцем явно; результаты опыта не меняются. Для T1 полная auth внутри доверенного кода не запрещена сама по себе: все штатные пути должны соблюдать policy, I01/I06 остаются обязательными в принятом scope. Окончательный выбор хранения и независимое review не выполнены; ADR остаётся Proposed, поскольку выбор модели угроз не является утверждением всей архитектуры.

## Свидетельство AUTH-01

По отдельному поручению владельца выполнен [опыт на его сессии в Simulator](../AUTH-01_RESULT.md): локальный запрет hidden не мешает getHistory/getPeerDialogs/peer search вернуть canary; новый контекст без login получает 401 AUTH_KEY_UNREGISTERED. ACR-001 получает runtime свидетельство. Соответствие исполняемого binary текущему SHA не установлено; независимое review остаётся открытым. D01 принят 2026-09-28; ACR-001 разрешён выбором scope. Статус ADR не изменён.
